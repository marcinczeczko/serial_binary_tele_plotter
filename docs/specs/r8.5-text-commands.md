# Spec: text commands, as a terminal (R8.5)

- Status: built (R8.5).
- Decision record: [ADR-0011](../adr/0011-text-commands.md) (proposed).
- Design canvas: the `Dashboard: terminal on a text device` board on the text-lines
  canvas (<https://claude.ai/artifact/EgT5RaZ5kTDfg9ZGFUx2fA>).
- Revised 2026-09-25 on the owner's call: a terminal (type a line, send it) instead of
  command templates in config; the board's replies are shown.

## Why

A text board is tuned by typing at it, as in Arduino's Serial Monitor: `PID 0 0.25 0.02`,
Enter, read what it answers. A terminal needs no command definitions, so a text profile
needs no config for sending at all.

## The terminal (Controls dock, text profiles)

For a text profile the Controls dock shows the **Terminal** instead of a panel:

- A transcript, newest at the bottom:
  - a sent line: its number (`▲ 3`, also the dashed marker on the plot at that moment,
    as for panel sends), the time and the line, in white;
  - a reply: a line from the board that matches **no stream pattern** (answers, debug
    prints, errors), in grey, with its time. Telemetry lines are never shown here.
  - at most 500 rows; the oldest go first.
- The input line under it, monospace:
  - **Enter** sends it, with the chosen line ending; the input clears.
  - **Up / Down** walk the lines sent this session (the last 50), as in a shell.
  - **Esc** clears the input.
  - Disconnected: disabled, with the placeholder `Connect to send`.
- A line-ending combo next to the input: `LF` (default), `CR LF`, `CR`, `none`,
  remembered per profile (`UiState`).
- Nothing else: no Send button (Enter sends), no clear button.

A binary profile keeps its panels and the command log unchanged.

## Sending

- The typed text is sent as ASCII plus the ending. A character outside ASCII is refused
  (`Not sent: only ASCII can be sent`), nothing is sent silently changed.
- The GUI hands the engine bytes (`send_packet(bytes)`), as for binary packets; the
  engine and transport don't change. A write error is reported as today.
- Sent lines aren't recorded (as panel commands aren't): a recording holds what the
  board sent, replies included.

## Replies (`core/protocol/text_line.py`, `stats.py`)

- `TextLineDecoder` keeps the newest unmatched lines in a ring of 200.
- The ~1 Hz `LinkReport` carries the unmatched lines since the previous report
  (`replies`, at most 100; beyond that `replies_dropped` says how many weren't shown).
  So the GUI gets a bounded batch once a second: no per-line signal (ADR-0002).
- A burst that doesn't fit is shown as one grey row: `… 37 more lines not shown`.

## Config

- No new keys. In a text profile, `commands` and `panels` are ignored with a warning
  (`a text profile sends from the terminal; commands and panels are for binary
  profiles`), since they would send binary packets to a text board.
- No schema change.

## Simulator

VIRTUAL on a text profile answers each line it's sent with `ok: <line>`, so the terminal
shows a reply. Nothing else changes in the simulation.

## Module plan

- `core/protocol/text_line.py`, `core/protocol/stats.py`: the replies ring and report.
- `core/acquisition/engine.py`: pass the previous report's count to `make_link_report`
  (already does: the report is computed from `prev` and `cur`).
- `core/transport/sim_transport.py`: the `ok:` answer in text mode.
- `core/config/document.py`: the warning for commands and panels in a text profile.
- `ui/panels/terminal.py` (new): transcript, input, history, ending combo.
- `ui/panels/container.py`, `ui/main_window.py`: the Terminal in the Controls dock for a
  text profile; sends, markers, replies from `_on_link_stats`.
- `ui/ui_state.py`: the line ending per profile.
- `README.md`: a Terminal section.

## Acceptance tests (R8.5 is done when these pass)

- Encoding: `PID 0 0.25` with `CR LF` is sent as `b"PID 0 0.25\r\n"`; `none` sends no
  ending; a non-ASCII line is refused and nothing is sent.
- Replies: unmatched lines reach the report in order, at most 100 per report with the
  rest counted; matched lines never do; a reset clears the ring.
- Config: `commands`/`panels` in a text profile are a warning; binary profiles unchanged
  (the pinned `0x10`/`0x11` bytes still pass).
- Simulator: a text VIRTUAL device answers `ok: PID 0 0.25`.
- `qt`: on a text profile from VIRTUAL, typing a line and Enter sends it; it appears as
  `▲ 1` with a plot marker; the `ok:` reply appears under it; Up recalls it; the ending is
  remembered per profile; the input is disabled when disconnected.
