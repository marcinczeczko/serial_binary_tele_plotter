# Spec: text commands (R8.5)

- Status: draft, for the owner's review. Nothing is built yet.
- Decision record: [ADR-0011](../adr/0011-text-commands.md) (proposed).
- Design canvas: the `Dashboard: sending to a text device` board on the text-lines canvas
  (<https://claude.ai/artifact/EgT5RaZ5kTDfg9ZGFUx2fA>).

## Why

A text profile (R8.3, R8.4) plots a board that prints lines. Tuning such a board means
sending it lines too (`PID 0 0.25 0.02`), and today the command panels can only send
binary packets. The panels, parameters, presets, Live mode and command log (R5.2, R6.3,
R6.4) already fit; only the encoding differs.

## Config shape

A text profile's command has a `template` instead of `packet_id` and `endianness`:

```json
"commands": {
  "gains": {
    "label": "PID gains",
    "template": "PID {motor} {kp} {ki}\n",
    "fields": [
      {"name": "motor", "type": "u8"},
      {"name": "kp", "type": "f32", "param": "kp"},
      {"name": "ki", "type": "f32", "param": "ki"}
    ]
  }
}
```

- `template` uses the **pattern grammar** (`core/protocol/text_line.py`): fixed text,
  `{name}` slots, `{{`/`}}` for braces. Its slots must be the `fields` in order, as for a
  stream's pattern: one rule for both directions.
- The line ending is part of the template (`\n` or `\r\n` in the JSON string), so what
  is sent is exactly what the file says.
- `fields` keep their meaning: `type` (range check and formatting), and a value from the
  button's `values`, a constant `value`, or a panel parameter (`param`, `column`).
- `panels` don't change at all.
- Like `frame.pattern`, `template` is allowed only in schema 3 (profiles), so no schema
  bump.

## Sending

- Values are resolved as today (`resolve_values`) and range-checked by type (a `u8` of
  300 is refused, as for binary).
- Formatting, chosen so that `atof`/`strtol` and Arduino's `toFloat()`/`toInt()` all read
  it:
  - integers (and `bool` in an integer field) as plain decimals: `0`, `-12`;
  - floats as the shortest text that reads back as the same `f32`/`f64`, **never with an
    exponent** (Arduino's `toFloat()` stops at `e`): `0.1`, `26.5`, `0.00012`;
  - NaN and infinity are refused (`Not sent: kp is not a number`).
- The encoded line is ASCII bytes. The GUI hands them to the engine as today
  (`send_packet(bytes)`); the engine, transport and recording don't change.

## Validation (`core/config/controls.py`)

In a **text** profile:
- `template` is required, must parse, and its slots must be the fields in order (errors);
- `packet_id` and `endianness` are ignored, with a warning;
- a template that doesn't end in `\n` or `\r` is a warning ("the board may never see the
  end of the line");
- the 255 B payload limit doesn't apply; a template over 1024 characters is an error.

In a **binary** profile: unchanged, and a `template` is ignored with a warning.

A command with errors is left out, with its buttons' panel, as today.

## Dashboard (see the canvas board)

- The Controls dock works for a text profile as for binary: edited vs sent, Live,
  presets, Esc revert. Nothing is disabled.
- The command log's last column is **Line** instead of Bytes for a text profile, showing
  the line sent with a `⏎` for its ending (`PID 0 0.25 0.02⏎`). "Send again" re-sends it.
- The status line: `Sent 'Update Left': PID gains (PID 0 0.25 0.02⏎)`.

## Simulator

VIRTUAL on a text profile reads what it's sent as the firmware would: it splits lines,
matches each against the commands' templates (the ending stripped) and hands the values
to the model (`PidMotorModel.apply_command`), so PID gains sent from a panel change the
simulated response, as they do for binary. Lines that match no template are ignored.

## Module plan

- `core/protocol/commands.py`: `CommandDef.template`; `encode_command` sends the line for
  a template command; `format_value` (the formatting above); `decode_text_command` for
  the simulator.
- `core/config/controls.py`: parse `template`; format-aware validation (the document's
  format is passed in, as for streams).
- `core/transport/sim_transport.py`: text commands in text mode.
- `ui/panels/command_log.py`, `ui/main_window.py`: the Line column and status text.
- `README.md`: the command section gains a text-profile example.

## Acceptance tests (R8.5 is done when these pass)

- Encoding: `PID {motor} {kp} {ki}\n` with 0, 0.25, 0.02 gives `b"PID 0 0.25 0.02\n"`;
  `1e-5` is sent as `0.00001`; an `f32` 0.1 as `0.1`; 300 in a `u8` and NaN are refused.
- Validation: a template whose slots don't match the fields is an error; a template in a
  binary profile and a `packet_id` in a text profile are warnings; a missing line ending
  is a warning; a binary profile's commands are unchanged (the pinned `0x10`/`0x11` bytes
  still pass).
- Simulator: a text VIRTUAL device given `PID 0 2.5 0.1\n` changes the left motor's gains.
- `qt`: a text profile with a panel sends a line from VIRTUAL; the log shows it with `⏎`;
  Send again re-sends the same bytes.
